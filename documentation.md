## Общее описание
SellerBot — это Telegram-бот для автоматизации обработки заявок на покупку/продажу телефонов с помощью ИИ (OpenAI GPT). Бот анализирует все входящие сообщения, определяет намерения пользователя, извлекает параметры сделки и управляет диалогом, используя бизнес-логику и подсказки (prompts).

---

## Архитектура и компоненты
- **TelegramUpdateMessageHandler** — основной обработчик входящих сообщений Telegram.
- **ConversationService** — сервис бизнес-логики, реализующий сценарии общения с клиентом и интеграцию с ИИ.
- **ActionProcessingService** — сервис обработки action из JSON-ответа GPT (SEND_TO_USER, ESCALATE_TO_HUMAN и др.).
- **ManagerReplyProcessingService** — сервис для обработки ответов менеджера и добавления новых моделей/цен.
- **Телеграм-бот** — класс TelegramBot, реализующий Telegram Long Polling API.
- **Сервисы интеграции с OpenAI** — ChatGptService, ChatGptServiceImpl.
- **Работа с базой** — репозитории на JPQL, сущности, миграции Flyway.

---

## Бизнес-логика и сценарии
- Все сообщения пользователя анализируются и обрабатываются через GPT (deal-system-prompt).
- Ответы GPT парсятся в DTO (GptDealResponse), реализована обработка action (SEND_TO_USER, ASK_USER, LOOKUP_BUYBACK_PRICE, ESCALATE_TO_HUMAN и др.).
- Вся логика обработки action вынесена в отдельный сервис ActionProcessingService.
- При необходимости (action ESCALATE_TO_HUMAN) бот автоматически отправляет запрос менеджеру. Менеджер может добавить новую модель и цену прямо из Telegram, данные автоматически сохраняются в базу.
- После добавления цены пользователю отправляется уведомление.

---

## Работа с ИИ (OpenAI)
- Используется OpenAI GPT (gpt-4o-mini или другая модель).
- Для бизнес-логики используется специальный prompt (deal-system-prompt), который задаёт сценарий общения.
- Ответы GPT должны быть строго в формате JSON, парсятся в GptDealResponse.
- Для интеграции используется сервис ChatGptServiceImpl.

---

## Работа с Telegram
- Входящие сообщения обрабатываются через TelegramUpdateMessageHandler.
- Для сообщений от менеджера (по chatId и userId) вызывается ManagerReplyProcessingService.
- Для всех остальных сообщений вызывается ConversationService, который реализует бизнес-логику с ИИ.
- Ответы пользователю отправляются через TelegramBotSender.

---

## Работа с базой данных и миграциями
- Используется PostgreSQL (docker-compose).
- Миграции управляются через Flyway (sql-скрипты в src/main/resources/db/migration).
- Все репозитории используют JPQL (@Query), никаких findBy... без явного запроса.
- Для тестовой среды volume для базы отключён, база пересоздаётся при каждом запуске контейнера.
- Для продакшена обязательно раскомментировать volume для сохранения данных.

## Структура проекта
- `src/main/java/ru/sellerbot/telegram` — обработчики Telegram-бота
- `src/main/java/ru/sellerbot/service` — сервисы бизнес-логики и интеграции с ИИ
- `src/main/java/ru/sellerbot/dto` — DTO для обмена данными и парсинга JSON
- `src/main/java/ru/sellerbot/model` — доменные модели
- `src/main/java/ru/sellerbot/persistence` — сущности и репозитории для работы с БД
- `src/main/resources/application.yml` — конфигурация приложения
- `src/main/resources/db/migration` — миграции Flyway
- `docker-compose.yml` — запуск инфраструктуры

## Настройка и запуск
1. Установите переменные окружения (например, OPENAI_TOKEN).
2. Укажите параметры в `application.yml` (токен Telegram-бота, модель GPT, prompts).
3. Соберите и запустите приложение (`mvn package && java -jar target/SellerBot-1.0-SNAPSHOT.jar`).
4. Запустите инфраструктуру через `docker-compose up -d`.
5. Добавьте бота в Telegram и начните диалог.

---

## Рекомендации для продакшена
- В docker-compose.yml обязательно раскомментируйте volume для базы данных, чтобы данные сохранялись между перезапусками.
- Все секреты (токены) должны храниться вне репозитория (используйте переменные окружения).
- Проверьте корректность миграций Flyway перед деплоем.
- Для production-режима настройте мониторинг и логирование.

---

## Расширение и поддержка
- Для добавления новых сценариев реализуйте новые action в enum Action и обработку в ActionProcessingServiceImpl.
- Для новых параметров телефона расширяйте PhoneInfoDto и соответствующие миграции.
- Для интеграции с другими каналами (например, WhatsApp) реализуйте отдельные обработчики сообщений.
- Для поддержки новых моделей GPT обновляйте gpt.model в application.yml.
